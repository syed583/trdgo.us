* 62 series, all HTTP 200; rows per series 201 to 2,258 (SPY 2,258: `pr` 753, `r` 753, `po` 752, i.e. one pre-market, one regular and one post-market row per session; fields `date open high low close volume total_volume market_time`, **no timestamps** on daily rows). Regular-session ('r') rows used for every return; no date has two regular rows (0 duplicates).

Missing regular sessions against the repo exchange calendar: **0 for 61 series**; FSUN has 15 missing sessions (2024-07-16 .. 2024-08-01, before its first event). 0 rows on non-trading days.
* Events: 441 past dated events. **434 reconstructed (GRADED)**, 4 PENDING_REACTION (reported 2026-10-29, reaction session not yet closed: ATR, FSLR, RDDT, INBK), 3 PENDING_TIMING (FSUN, provider label `unknown`). All 50 symbols have graded events (min 2, median 9, max 9). 36 upcoming events are not scored.

Five series show large one-day jumps (CNC -40 % on 2025-07-02; LRN +39 % and -54 %; NVCR +49 %; PRLB +39 %; RDDT +42 %): LRN, PRLB and RDDT coincide with their own earnings reactions; CNC and NVCR are not earnings dates and are unexplained here. These are not split-shaped, but because adjustment is undocumented this does not prove the series are split-adjusted; the 4 events within 8 days of a jump are flagged `near_price_jump` and kept out of the strict candidate set.

## 3. Independently reconstructed reaction returns
Method (Phase 2A rule, unchanged code imported from `earnings_outcomes.py`): BMO = previous trading day's regular close -> earnings-day regular close; AMC = earnings-day close -> next trading day's regular close; flat band +-0.5 %; the session is chosen with the repository's exchange calendar. **Labelled "next-session close-to-close"; not an immediate reaction.**
* 434 returns: median |move| 4.37 %, mean +0.68 %, 10th / 90th percentile -8.3 % / +10.1 %. Outcome classes: **UP 209 (48.2 %), DOWN 192 (44.2 %), FLAT 33 (7.6 %)**; so "always BUY" would score 48 % strict hits on this sample before costs.
* **Provider cross-check:** the provider's `post_earnings_move_1d` equals our reconstructed return for **all 434 events** (same sign 434/434; median absolute difference 0.00 percentage points; all within 0.15). Convention test: for BMO events the provider matches previous-close -> day-close (median diff 0.003) and for AMC events day-close -> next-close (0.003); the other conventions (e.g. BMO day-close -> next-close, gap-to-open) differ by 2.6-4.8 points. Meaning: the provider uses the same windows **given its own label**, and both come from the same price source, so this validates our window and calendar logic, not the label and not independence of the price data.

## 4. Release timing: verified versus uncertain
* **Verified public release timestamps: 0.** No source in H1a/H1b carries one. SEC acceptance is recorded only as **SEC filing acceptance time**. Because a company can file later than it publishes, acceptance is treated only as an **upper bound** on the release time:
  * provider BMO and accepted at or before 09:30 ET on the event date (including the evening before): **SUPPORTS_BMO** (the release was before the open): **211** events;
  * provider AMC and accepted at or after 16:00 ET: **NOT_CONTRADICTED_AMC** (consistent, but it does not prove the release was after the close): **215**;
  * provider AMC and accepted before 16:00 ET on the event date: CONTRADICTS (none found);
  * provider BMO but accepted later in the session: UNINFORMATIVE_LATE_FILING: 1 (PFS 2025-07-24);
  * no 8-K Item 2.02 match within +-3 days: **11** (EDU 9 events, SPFI 1, EXLS 1; all histories reach 2024-10), 3 events with provider label unknown.
* So **no AMC label can be positively verified from SEC data**; strict timing verification would need minute-level price evidence or a company press-release time, neither collected.
* An earlier simple comparison (21 "inconsistent" events) disappears under the upper-bound reading: 9 CNC events and WT 2025-08-01 are BMO events whose 8-K was accepted the evening before (release before the open, same reaction window); 8 PFS events, WT 2025-10-30 and WM 2025-01-29 are AMC events filed later (next morning, or 20:55 ET the same evening); PFS 2025-07-24 is the one BMO event filed late (14:53 ET).
* Acceptance day offset vs the event date: same day 409, +1 day 9, -1 day 10, -3 days 1.

### The nine timing-label conflicts (provider label vs the application's per-symbol label)
The application's prediction label is **one label per symbol** (this season); the provider label is **per event**. For TMUS the provider says premarket in 2025-01, 2025-10, 2026-02, 2026-07 and postmarket in 2026-04 and 2026-10; SPFI alternates the same way; KVUE reported postmarket on 2026-02-17 and premarket in other quarters. **The same company changes session between quarters.** Findings per conflict (`h1b/label_conflicts.json`):
* TMUS x4, SPFI x2: SEC acceptance 06:29-09:00 ET before the open = supports the provider's premarket label; the application's single AMC label was the wrong comparison.
* KVUE 2026-02-17: SEC 16:46 ET, consistent with the provider's postmarket label.
* WT 2025-10-30 (provider postmarket): SEC accepted next morning 08:00 ET: late filing, not contradicting.
* PFS 2025-07-24 (provider premarket): SEC accepted 14:53 ET same day: uninformative; unresolved.
Conclusion: 7 of 9 are real session changes supported by filings, 2 remain unresolved (WT, PFS). **A per-symbol timing label must never be used; timing is per event.** This is an important input for the Smart Move design (and for the existing application's single label per symbol).

## 7. Is a defensible Track H backtest feasible?
**Partly, and only in a narrow sense.**
* **Event discovery and labels: yes.** Prices, calendar, windows and per-event timing give 434 reconstructed next-session returns on 50 names over 10 quarters, cross-checked against the provider with exact agreement.
* **A pre-earnings prediction backtest: not yet defensible.** (1) Release timing is unverified for every event (AMC cannot be positively supported from SEC data). (2) The only features with point-in-time standing are price-derived (category 5, 3 from prior events, 8) and, if the next stage proves it, IV rank (category 7); the model would be a partial-evidence score (max 40 of 100 points), never the full model. (3) 50 symbols / ~430 events / 10 quarters is small and survivorship-biased (today's universe), so only wide intervals are possible. (4) The provider's historical session labels and all consensus / expected-move fields lack as-of proof.
* What H1b does support: a clean **price-only baseline study** (base rates by class, reaction-size distribution, BUY/SELL/FLAT separately, simple trend/earnings-history rules) using only information stamped before the cutoff, labelled as exploratory.
* Decision needed before any volatility stage: whether to accept "timing not contradicted" with a 24 h conservative cutoff for BMO/AMC, or to require extra timing evidence first.
